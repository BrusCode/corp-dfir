# Corp-DFIR — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Coletar artefatos de agentes de IA e logs de acesso remoto de PCs Windows via Tactical RMM e analisá-los num Ubuntu local.

**Architecture:** O coletor PowerShell copia os arquivos, gera o manifesto com hashes e envia um zip por HTTPS. No servidor, a API FastAPI guarda a evidência imutável; workers Taskiq (com Redis) extraem eventos e aplicam regras YAML; a triagem por LLM é opcional. Tudo fica em SQLite e é exibido num painel HTML, com Caddy fazendo TLS e Basic Auth.

**Tech Stack:** PowerShell 5.1; Python 3.12, FastAPI, Taskiq + taskiq-redis, PyYAML, Jinja2, httpx, pytest; Docker Compose, Redis 7, Caddy 2.

## Global Constraints

- O staging no PC é **sempre** `C:\ProgramData\CorpDFIR\`, que é a única exceção do Bitdefender.
- O coletor roda em prioridade `Idle`, com pausa de 150 ms entre arquivos; ignora arquivos acima de 200 MB e limita o pacote a 2 GB.
- `.pfx`, `.p12` e `.key` **nunca** são copiados: entram no manifesto só com hash e metadados.
- A evidência original fica imutável (`chmod 0444`); o processamento acontece numa área de trabalho separada.
- O painel e o LLM recebem segredos **mascarados**; a correlação é feita pelo SHA-256 do segredo.
- A triagem por LLM fica desligada se `LLM_BASE_URL` estiver vazio.
- O upload exige o cabeçalho `X-DFIR-Token` e o `X-DFIR-SHA256` precisa bater com o arquivo recebido.
- Porta 8443, TLS autoassinado.
